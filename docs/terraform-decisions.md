# Terraform decisions

Choices made while building the `terraform-dev` environment in [`infra/terraform/`](../infra/terraform), with the reason for each. Source material for a later architecture document.

## Scope and environment

| Decision            | Choice                                                                  | Reason                                                                                                                                                            |
| ------------------- | ----------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Infrastructure tool | Terraform, intended to replace the CloudFormation templates in `infra/` | One tool for every resource, including the Forum table and API host that had no template. Retiring the team's stacks needs team agreement and `terraform import`. |
| Account             | Team account `320465872576`, environment name `terraform-dev`           | Personal account not available; distinct names avoid clashing with the team's live `dev` resources.                                                               |
| Running Terraform   | Locally first; GitHub Actions pipeline later                            | Learn the workflow before automating it.                                                                                                                          |
| Applying            | An admin runs `apply`; `eline-dev` runs `plan`                          | `eline-dev` cannot create IAM roles (`iam:CreateRole` denied).                                                                                                    |

## Code and state

| Decision        | Choice                                                                                  | Reason                                                                                                                                                     |
| --------------- | --------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Layout          | One folder, one file per area (`hosting.tf`, `auth.tf`, …)                              | Easy to read; dev and prod differ only by variables.                                                                                                       |
| Configuration   | `.tf` files and `.terraform.lock.hcl` in Git                                            | Reviewable changes; everyone uses the same provider versions.                                                                                              |
| State           | S3 bucket `lecturekaki-tfstate-320465872576`, created by `infra/terraform/bootstrap/`   | Private, versioned and locked (`use_lockfile`); shared by local runs and the future pipeline. Not in Git: the repository is public and Git has no locking. |
| Bootstrap state | Local file, Git-ignored                                                                 | Only records the state bucket; rarely changed.                                                                                                             |
| Build output    | `build/` stays Git-ignored                                                              | The ingest package is ~16 MB and changes on every rebuild; whoever applies runs `package_ingest.py` first.                                                 |
| Tags            | `Project`, `Environment`, `ManagedBy=terraform` on every resource                       | Tells Terraform resources apart from the team's in a shared account.                                                                                       |
| Runbook         | [Terraform deployment](terraform-deployment.md): bash commands from the repository root | One ordered list for whoever applies, including the package build and frontend upload.                                                                     |

## Resources

| Area                   | Choice                                                                                                                  | Reason                                                                                                                                                        |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tables                 | `lecture-kaki-timetables-terraform-dev`, `lecturekaki-terraform-dev-forum`; on-demand; no backup or deletion protection | Team naming with `dev` → `terraform-dev`. Test copy, so no extra protection.                                                                                  |
| Website                | New bucket and CloudFront distribution copying `hosting.yaml`; `PriceClass_200`; `force_destroy = true`                 | Same behaviour as the team's site; test copy can be torn down in one step.                                                                                    |
| Frontend upload        | `aws s3 sync` after `apply` (assets first, then `index.html`), not Terraform                                            | Build files change every release; uploads need per-file cache rules and ordering.                                                                             |
| Login                  | New Cognito pool `lecture-kaki-terraform-dev`, copying `auth.yaml`                                                      | Independent from the team's pool; rehearses moving auth to Terraform. Accounts are not migrated (Cognito cannot export passwords, and user IDs would change). |
| Login return addresses | Website plus `localhost:5173`, `:8080` and `:8000/docs`                                                                 | Allows local testing against this environment.                                                                                                                |
| Lecture ingestion      | Copy of `ingest.yaml`; weekly schedule as the team; package built with `package_ingest.py` before `plan`                | Same behaviour; Terraform has no SAM, so the scheduler and its role are explicit.                                                                             |
| Failure alert email    | Variable `alert_email`, empty for now                                                                                   | Can be set later; only the email subscription is added.                                                                                                       |

## API server

| Decision             | Choice                                                                                  | Reason                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| -------------------- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Live Forum updates   | Stay in memory (one API process)                                                        | No extra infrastructure or code change; acceptable at class scale. Restarts drop live connections briefly.                                                                                                                                                                                                                                                                                                                                                                                       |
| Host                 | One EC2 server, mirroring the team's `lecture-kaki-api-host-dev` stack                  | Matches the live setup, easing a later migration.                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Size                 | `t3.micro` with 2 GB swap, Amazon Linux 2023, 20 GB disk                                | Team's choice; swap lets the image build finish on 1 GB.                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Code delivery        | Server builds the image at first boot from a pinned commit (`source_revision`)          | Team's choice; pinning stops rebuilds from silently taking new code.                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Address              | Elastic IP                                                                              | Address survives stop/start.                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| HTTPS                | Caddy with a short-lived Let's Encrypt certificate for the Elastic IP                   | Team's choice; no domain or extra CloudFront needed. Ports 80 (validation, redirect) and 443 (API) open to all.                                                                                                                                                                                                                                                                                                                                                                                  |
| Access               | Session Manager; no SSH                                                                 | No keys or open SSH port.                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Config changes       | `user_data_replace_on_change = true`: any change to the boot script replaces the server | cloud-init runs the boot script only on a server's first start. By default (the team's stack and Terraform's `false`), a changed script is stored after a stop/start but never run, so a new `source_revision` or changed Cognito, table or website value silently keeps the old code and settings. Replacing the server makes the change take effect, at the cost of 5–10 minutes of API downtime while the new server builds; the Elastic IP keeps the address. Differs from the team's stack. |
| Considered, not used | CloudFront in front of the API with a firewall and secret header                        | Replaced by the team's Caddy approach once IP certificates were confirmed.                                                                                                                                                                                                                                                                                                                                                                                                                       |
